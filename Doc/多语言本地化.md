# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 31 种语言、138 条后台消息（含 Hosting 扩展）；面板 117 条界面词条，英文源文 + 31 种译文｜英文为源文与兜底

## 2. 词表文件

- `NewLife.Agent/Locales`：主库与 Hosting 扩展共用的运行时消息（Hosting 依赖主库，避免多程序集并发注册丢失词条）。

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。

## 2.1 语言选择与请求语言

- `NewLife.Setting.Language`（Core 全局配置项 `Language`，持久化到 `Core.config`）显式指定界面与日志语言，如 `zh-Hans`、`fr`；为空时跟随操作系统。本库不再单独维护语言配置项。
- Core 保存配置后立即生效（`NewLife.Setting.Save` 调用 `ApplyLanguage`），切换语言无需重启进程（菜单描述在显示时翻译，同样立即跟随）。
- 语言名无效或该语言没有词表时保持自动识别，避免进程被锁在英文。
- Web 请求语言由 NewLife.Core 的 `HttpServer` 默认按 `Accept-Language` 设置：优先 `NewLife.Setting.Language` 全局配置，其次浏览器语言，最后服务器语言；本库不再维护请求 Cookie。
- 主界面右上角提供语言下拉框（`/api/Languages` 取列表）：选择写入 `NewLife.Setting.Language` 并立即生效；选择 `🌐` 恢复按 `Accept-Language` 自动识别。登录页不再单独提供语言选择，跟随浏览器语言。

## 3. 新增一条消息

1. 代码中写英文源文：`throw new XException("Session {0} is closed.", sessionId);`，日志直接写英文模板（`Logger.Format` 自动翻译）。
2. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
3. 运行校验脚本确认键集合、占位符与格式说明符一致。

配置项描述同样以英文为源文写在 `Setting` 的 `Description` 特性中；`/api/ConfigMetadata` 按当前语言翻译描述，并取译文首句作为显示名，无需单独维护显示名词条。

保存 Xml/Ini 配置文件时，配置提供者按当前语言翻译注释，因此 `Agent.config` 里的 `<!--服务名-->` 等注释也跟随语言变化；缺少译文时保持英文原文（依赖 NewLife.Core 的配置注释本地化能力）。

命令处理器（`BaseCommandHandler`）的 `Description` 保存英文源文，`CommandFactory.GetShortcutMenu` 在生成菜单时翻译，因此切换语言后菜单立即跟随，不会在类型初始化时冻结。

## 3.1 Web 面板界面

面板 `index.html` 以**英文为源文**，`WebPanel/wwwroot/i18n/{语言}.json` 保存英文到目标语言的映射（一个键值对一条界面文案）：

- 服务端输出首页时按当前语言做**最长匹配替换**（英文词条带词边界，避免命中脚本标识符中的同名片段），命中 `<title>`、文本节点、`placeholder`/`title`/`aria-label` 属性与脚本字符串；当前语言优先取 `NewLife.Setting.Language` 固定的语言，未配置时跟随请求 `Accept-Language`；英文即源文，直接输出。
- `i18n/en.json` 为英文基准词表（键值相同），供校验与英文对照；`i18n/zh-Hans.json` 等 31 个语言文件保存译文。缺少对应语言文件时保持英文源文。
- 新增界面文案：先在 `index.html` 写英文，再在 `i18n/en.json` 登记并到全部 `i18n/*.json` 补齐同名键；单元测试 `UiDictionaries_CompleteAndConsistent` 会校验各语言键集合与英文基准一致、英文基准键都出现在源文中，并禁止词条出现 `<`、`>`、`&`、引号、反引号、反斜杠与 `${`（词条会直接替换进 HTML 与脚本，这些字符会破坏页面）。
- net40 目标不编译 Web 面板，`wwwroot`（含 `i18n` 词表）不嵌入 net40 程序集，避免无效体积。

## 3.2 语言切换与状态同步

- `NewLife.Setting.Language` 是唯一事实源：**空值表示自动**（跟随请求 `Accept-Language`），非空表示固定语言；`Localization.Culture` 在进程内生效。
- `/api/languages` 返回 `items`、`current`（原始配置）、`selected`（归一化后的配置值，空=自动）、`effective`（实际生效语言）与 `forced`（是否固定）。前端下拉框的 value 必须使用 `selected`：配置为空时选中 `🌐 Auto`，**不能**选中某个具体语言，否则 select 值与配置不一致。
- `🌐 Auto` 文案附带当前实际语言，如 `🌐 Auto (English (United States))`；语言名称来自 Core `Localization.GetLanguageOptions()`，按当前界面语言本地化。
- 首页注入 `window.__panelLanguage={selected,effective,forced}`，前端首屏即可拿到后端语言状态；登录页的 `loadLanguages()` 仍会请求 `/api/languages`，请求完成前使用服务端已渲染的页面语言（自动模式即浏览器语言）。
- 接口超时/失败或 `selected` 为空时前端不做切换；固定语言与页面语言不一致时，`switchLanguageIfNeeded` 通过 sessionStorage 防抖后只刷新一次。选择具体语言写入 `NewLife.Setting.Language` 并立即生效，选择 `🌐 Auto` 清空配置回到自动；刷新后服务端按新语言渲染，API 消息同步使用同一语言。
- RTL：`UiLocalization` 为 ar/he/fa 输出 `dir="rtl"`；面板 CSS 使用逻辑属性（`inset-inline-*`、`margin-inline-*`、`text-align:end`），并为开关滑块、toast 动画补充 `[dir="rtl"]` 规则。

## 3.3 应用标题与描述

`AssemblyTitle` 与 `Description` 均已改为英文源文，并加入全部 `Locales`（当前 138 条运行时词条）。`ServiceName` 永不翻译；`DisplayName`/`Description` 的**显示与安装注册**都按当前语言翻译，原始配置值保持不变。

- `ServiceBase.DisplayTitle` / `DisplayDescription` 只翻译用于显示和安装注册的副本；`Agent.config` 中的 `DisplayName`/`Description` 保持原文。
- 显示点：控制台标题、`ShowStatus`、Web 面板 `/api/Status` 均使用这两个属性。
- 注册点：`Install` 命令在构造 `ServiceModel` 时使用 `DisplayTitle`/`DisplayDescription`，因此 Windows SCM、systemd、procd、rc.d、LaunchAgent 写入的是**安装时语言**的显示名与描述。
- 用户配置的 `DisplayName`/`Description` 同样会走一次 `L.T`；没有对应词条时原样使用，因此自定义品牌名不受影响。
- 服务安装后再切换界面语言不会改写已注册信息；需要更新注册语言时重新执行安装/重装命令。
- `Agent.config` 的 `DisplayName`/`Description` 保存英文源文，**不保存译文**；配置注释会按当前语言本地化，但配置值不会。验证本地化请看控制台状态、Web 面板或系统服务注册信息。
- NuGet 包元数据（`Description`、`PackageReleaseNotes`）使用英文，不随界面语言翻译；运行时翻译只影响显示与注册。
- `check-locales.ps1` 的孤儿键扫描已覆盖 `.csproj`，可直接识别标题与描述源文。

## 4. 带前缀日志

日志前缀（如 `[Agent]`、服务名）不参与本地化：先按日志语言翻译并格式化消息，再拼接前缀。

- 服务内：`WriteLogPrefixed("[Agent] ", "Service started: {0}", reason)`
- 任意 `ILog`：`log.WriteLogPrefixed(LogLevel.Info, "[Agent] ", "Service started: {0}", reason)`
- 与 NewLife.Core 的 `LogExtensions.WritePrefixed` 语义一致；net40 目标引用旧版 Core，由本库提供等价实现。

禁止写成 `WriteLog($"[{ServiceName}] 服务启动")`：整串查表必然回退英文，前缀也会被当成源文的一部分。

## 5. 校验

```powershell
pwsh -File check-locales.ps1 -LocaleDir NewLife.Agent/Locales -SourceDir .
```

CI 的 localization job 会遍历所有含 `Locales` 目录的项目并执行同一脚本。脚本当前校验：

- 错误：键集合与基准一致、无多余/孤儿键、无空译文、首尾空白与英文键一致、占位符与格式说明符一致。
- 警告：值等于英文键的长短语（疑似未翻译）、占位符序号跳号。

面板界面词表由单元测试校验（`LocalizationTests`），随 `dotnet test` 一起执行；新增或修改界面文案后运行该测试即可发现漏词条与多余键。
